## 1. 逆向方法（可复现）

关键教训（踩过的坑，写下来避免重犯）：

1. **androguard 4.1.4 的 `d.get_strings()` 返回纯 Python `str` 列表**，不是 `StringDataItem`。
   写 `s.get()` 会抛 `'str' object has no attribute 'get'`；写成 `except: None` 会把全部字符串变成 `None`，
   于是「找不到任何命令名」——我第一轮就是这样白白跑了一遍。
2. **`const-string` 的 `ins.get_output()` 是 `v1, "reqRoleInfo"`（含引号的字符串值）**，
   不是 `string@44705`。要用 `re.search(r'"([^"]*)"', out)` 提取。
3. **`const` / `const/4` / `const/16` 的 `ins.get_operands()` 是 2 元组**
   `(Operand.REGISTER, n)`、`(Operand.LITERAL, value)`。
   我最初写 `len(o) >= 3` 过滤，结果**一个常量都取不到**（表现为「已知道操作码 0 个方法出现」这种荒唐结果）。
   直接用 `get_output()` 正则 `,\s*(-?0x[0-9a-fA-F]+|-?\d+)$` 更稳。
4. `ins.get_kind()` 在这个 dex 上会 `IndexError`，别用。

主要脚本：

| 脚本 | 作用 |
|---|---|
| `analyze1.py` / `analyze2.py` | 找引用命令名字符串的方法 + 该方法内的常量候选 |
| `analyze3.py` | 命令名 ← 向前找最近 const（操作码） |
| `dumpsmali.py` | dump 指定方法完整反汇编（本报告全部证据出处） |
| `extract_dispatch.py` + `dispatch_clean.json` | 从响应分发器抽取 **456 条** 响应 op → 处理函数 |

| `sent_ops.py` | 枚举客户端经由 `Ls/a;->z(S [B)Z` 发出的请求操作码 |

## 7. 未确认 / 存疑部分（明确标注，未编造）

1. **op 4128 没有客户端命令名 —— 未确认。**
   全 DEX 里 **不存在值等于 4128（0x1020）的 `const/const-4/const-16/const-high16` 指令**
   （`find_opcodes.py` 精确扫描，结果为 0）。
   而 `Ls/a;->z` 的调用点枚举里也**没有 4128**。
   ⇒ 结论：客户端**不主动发 4128**，该包是**服务端主动推送**（周期性资源刷新）。
   仅有响应侧的分发条目存在。**「4128 对应的请求命令名」= 未确认，不要当成 `reqRoleInfo`。**

2. **`data/f;->c` 的语义 = 未确认。**
   它是 op 4384 响应中**紧跟角色名 UTF-8 之后的那 1 个字节**，
   恰好与委托里「等级=7 紧跟在角色名之后 1 字节」的描述吻合；
   但我**没有**在代码里找到把它当「等级」用的确凿证据
   （`sget-byte data/f;->c` 附近唯一的等级相关标签是 `di_提示等级不符`，出现在 `LscriptPages/game/g;->i0()I`，
   关联度不足以定论）。**因此只写「很可能，但未确认」，不算结论。**

3. **op 4100（gameLogin）响应包未逐字段映射。**
   其处理函数是 `LscriptPages/game/a0;->S([B)`，是一个上千行的「全局登录状态」大解析器
   （读职业列表、RMS、多段数组…），本次**没有**做逐字段表。
   如果上一轮说的「等级=7」确实来自 op 4100 的某个子段，需要另做一轮专项分析。

4. **`Ls/a;->z(S [B)Z` 是发送队列这一点** 由 `La0/a;->p5()`（4356 → 宝藏响应）推断而来，
   逻辑自洽、锚点齐全，但 `Ls/a;->z` 本身的注释性证据（方法名/日志）不存在（混淆）。

5. **`di_标题个数` / `t2("treasureList")` 的口径**：
   角色信息面板画的是 `La0/a;->A9.length`（原始包条目数），
   「我的宝藏」面板用的是 `La0/a;->t2("treasureList")`（客户端列表模型的非零条目数）。
   两者**通常相等但来源不同**；哪个是游戏 UI 上真正显示的「宝藏数量」，取决于具体面板 —— **未逐一确认**。

6. 本报告未涉及 APK 内 `assets/data/*.dat`（9475 个）与 `assets/script/*.sc`（226 个）
   这两个加密/加壳资源层；若某些配置型上限（例如等级相关上限表）来自那里，则不在本报告范围内。
